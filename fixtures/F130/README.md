# F130

`csh init --subject` over a small TypeScript shop with requirements headed by identifiers, a guide, a changelog, a
feature whose Rules carry their own tag (`@rule-1`) and a requirement tag (`@REQ-1`), cucumber step definitions, a
Vitest test, a test fixture, built output, a shell script and a beads issue list. The proposal finds the identifier
family REQ (two or more identifiers) and not ABC (one), SHA or UTF (external); reads the rule tags as the rules' own
identifiers and the REQ tags as citations; puts the step definitions with the tests under `style: cucumber`; leaves
the changelog, the built output and the fixture out; and, with Vitest in package.json, names the results file. The
subject has no remote, so the guess says the manifest is not portable. Coverage counts 11 of the 15 tracked files.
The proposed manifest, run as it stands, reads the requirements and the citations of the test and the rule.
From real runs ([13](../../docs/spec/13-from-real-runs.md)), section 1; stage 38.
