## 4. Root cause analysis

- **Q1. Why does stale prose only grow from release to release?** Lines are written once, when a feature lands, and the files they name go on changing. Review reads the lines a change edits, not the lines that name the files it changes, so nothing brings an old line back for reading. The two jumps are the releases that added documents: v10.0.0 (the charter) and v11.0.0 (the guides from 15 to 27). 5 Whys to the root, below.
- **Q2. Why do refuted claims survive releases that pass every gate?** The facts they state (the Node floor, the entry points, the unit tier's size, the compatibility date) are hand-typed in prose. ESI.ts generates some counts into prose through markers (etc/doc-metrics.json), but these sentences are outside the markers, so no generator or check touches them. Four of the eight are older than the code that refutes them: the code moved and the sentence did not. Evidence: finding f184674b8c71fca6 at stage v11-3-0. Two whys: hand-typed, and outside the markers.
- **Q3. Why are eight requirements unverified though every gate passes?** Their Verified-by lines name prose (code review, a process) rather than a check, and no test cites them. The status column says Enforced or Practised regardless. Nothing ties a status to a mechanism the repository holds. One why: the status is asserted, not derived.

### The 5 Whys

1. **Why is a line stale?** A file it names changed after the line was last written.
2. **Why was the line not updated with the file?** The change that edited the file did not touch the document, and review looked only at the change.
3. **Why did review not look at the document?** Nothing links a file to the lines that name it: the link exists only as a path inside a sentence.
4. **Why does nothing link them?** The guides and the charter are checked for their own form (Markdown lint, EARS audit, link checks), never against the history of what they name.
5. **Why are they checked only for form?** Each practice is judged on its own terms, and no practice owns the relation between a sentence and a file.

No practice owns the relation between prose and the code it names.
