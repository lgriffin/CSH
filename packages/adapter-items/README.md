# @csh/adapter-items

## Purpose

`@csh/adapter-items` reads a codebase's documents, feature files, test files and issue exports as an inventory: each requirement, rule, scenario, test file, document and issue is one item, and each reference between them, or from an item to a file, is one edge. It reads structure and never meaning, and it lifts no claim ([11](../../docs/spec/11-ingesting-a-codebase.md), stage 22). [The manifest guide](../../docs/guides/manifest.md#inventory-sources-stage-22) shows how a profile names these sources.

## Where it sits

It belongs to the "Adapters" container, shown in the [containers diagram](../../docs/architecture/containers.mmd), as the inventory readers in [components-adapters.mmd](../../docs/architecture/components-adapters.mmd). `@csh/run` runs each of its four adapters in the isolated adapter subprocess, for sources of kind `Documents`, `Features`, `TestFiles` and `Issues`, or for a practice that names one. The check engine resolves the edges they produce (`@csh/check`, `trace`).

## Public interface

- `@csh/adapter-items/markdown`: `adapter` (id `csh.adapter.items.markdown`), `run(input)`, `firstSentence(value)`. One `document` item per file; a heading that opens with an identifier is a `requirement` item, its heading parts and `- **Name:** value` bullets its fields; `verified-by`, `implements` and `mentions-file` edges, and since stage 24 `mentions-symbol` (a backticked symbol beside its code file) and `mentions-script` (`npm run <name>`), which trace checks against code facts ([A-106](../../ASSUMPTIONS.md)). Since stage 25 a backticked bare file name (`bareFileToken`), such as `security.test.ts`, is a `mentions-file` or `verified-by` edge too ([A-110](../../ASSUMPTIONS.md)). Settings: `idPattern`, `headingFields`, `verifiedField`, `headings`. Since stage 55, `told: sentences` lifts told rules from prose (`told.ts`): each sentence outside a code fence, a heading, a table, HTML and an identified item's section that is an EARS sentence, or names a dependency and restricts it (`does not import`, `never depends on`, `independent of`, `knows nothing about`, `not bound to`), is a `requirement` item with the id `<path>#L<line>`, attributes `lifted` (`ears` or `layering`) and `sentence`, cited as the sentence and never translated ([A-190](../../ASSUMPTIONS.md)). Since stage 56 a lifted sentence that claims something checks it ("guaranteed", "enforced", "covered by tests") carries the attribute `claims`, the phrase as written ([A-192](../../ASSUMPTIONS.md)).
- `@csh/adapter-items/gherkin`: `adapter` (id `csh.adapter.items.gherkin`), `run(input)`. `feature`, `rule` and `scenario` items; a rule carries its EARS pattern; `exemplifies` edges from each scenario to its rule; `cites` edges from tags matching the `tagCites` setting. Since stage 57 a scenario's `cites` and `exemplifies` edges carry `observes`, the words of its title, background, steps and examples, and `reader` `gherkin` ([A-196](../../ASSUMPTIONS.md)).
- `@csh/adapter-items/tests`: `adapter` (id `csh.adapter.items.tests`), `run(input)`. One `test-file` item per file with its test count; `cites` edges from identifiers in test titles. Since stage 26, when the practice names a results file (`executions`), each test the runner reports is joined to its file and to the identifiers its full name cites, as `results`, and each file's `passed`, `failed`, `errored` and `skipped` counts replace its attributes, the declared `skipped` too ([A-115](../../ASSUMPTIONS.md)); a nested file wins over a shorter path that also ends the runner's; `no-results`, `results-unmatched` and `results-missing` say what could not be joined. Since stage 28 a `csh-results/v1` file, which names no test, is read the same way, and is joined only at the commit it names; at any other it joins nothing and warns `results-other-commit` ([A-124](../../ASSUMPTIONS.md)). Since stage 35, `.py`, `.java`, `.go` and `.rs` files are read by their runners' conventions (`tests-other.ts`): pytest functions and classes, JUnit annotated methods, Go `TestXxx`, `FuzzXxx` and output examples in `_test.go` files, and Rust `#[test]` functions; names, docstrings, doc comments, `@DisplayName` and `@Tag`, pytest marker strings and literal `t.Run` names cite, and an underscore in a name reads as a hyphen when the identifier pattern cannot hold one ([A-128](../../ASSUMPTIONS.md)). A result whose runner names no file (`tests-join.ts`) is joined by what the source's files declare: a Surefire or Gradle classname (`a.b.C`, `a.b.C$Inner`, `a.b.C.Inner`) to the `.java` file whose `package` and top-level type it names, else to the one file whose path ends `a/b/C.java`; a `go test -json` import path to its directory (by the `module` line of a `go.mod` in the source, else the longest directory of `_test.go` files the path ends with) and then to the one file there declaring the test; a cargo-nextest binary id and test path to the one `.rs` file of that target, in the crate a `Cargo.toml` in the source names, whose `#[test]` function has that module path. A result that two files fit is not joined, and `results-unmatched` counts it apart; a `go.mod` or `Cargo.toml` is read for its layout and is not an item ([A-134](../../ASSUMPTIONS.md)). Since stage 57 each `cites` edge from a test carries its grain, `observes` (`observedIn`): the identifiers its body mentions in code and each string in it that is a single identifier; a TypeScript body is the test's call, in the other languages it runs to the next declared test. `reader` names the language that read it, and a second test in the file citing the same item widens the one edge ([A-196](../../ASSUMPTIONS.md)). Settings: `idPattern`, `citePattern`.
- `@csh/adapter-items/yaml` (stage 28): `adapter` (id `csh.adapter.items.yaml`), `run(input)`, `parseYaml(text)`. The structured trace adapter for `Traces` sources: one `property` item per entry of a YAML or JSON list, such as a security model's properties; the edges, attributes and recorded silence the practice maps ([A-122](../../ASSUMPTIONS.md)). Settings: `collection`, `idField`, `textField`, `edges`, `fields`, `silence`. Its YAML is a subset read with no library; a line it cannot place is `malformed-yaml`.
- `@csh/adapter-items/jsonl`: `adapter` (id `csh.adapter.items.jsonl`), `run(input)`. One `issue` item per JSON line, with status, priority and type; `mentions` edges. Setting: `idPattern`.
- `@csh/adapter-items`: the five modules as namespaces, and `common` (`pathToken`, `slug`, `unique`, `backticked`, `DEFAULT_ID_PATTERN`).

## Depends on and used by

- Depends on: `@csh/kernel` (digests, ordering), `@csh/witness` (the adapter contract, items and edges) and `@csh/adapter-ears-markdown` (`classify`, the EARS pattern of a sentence). No external packages.
- Used by: no package imports it at run time. `@csh/run` names its subpaths in `BUILTIN_ADAPTERS` and depends on it so that they resolve. `subjects/esi-ts` reads ESI.ts through it.

## Invariants it protects

- Every item and edge carries a span, `path:line`, and output never depends on the order files were read in.
- An identifier defined twice in one source is the error `duplicate-id`, and the second is not read. A feature file with nothing to read is the warning `no-items`, and a test file with no test the information `no-tests` (P4).
- Only what the source states is read: a requirement whose verification is prose alone gets no `verified-by` edge, and nothing guesses one ([A-97](../../ASSUMPTIONS.md)).
- Text inside a Markdown code fence or a Gherkin doc string is never structure; a fence closes only on one of the same character at least as long as the one that opened it.

## Rationale

The existing adapters lift claims, and a mature codebase states most of what it means in prose, feature files and tests that no step table or binding covers yet. An inventory makes that material visible to the gap view first: what exists, what refers to what, and what refers to nothing. Adapters stay outside the core ([ADR-12](../../docs/adr/ADR-12-adapters-outside-core.md)) and run isolated with bytes as input ([ADR-20](../../docs/adr/ADR-20-adapter-isolation.md)), so an inventory adapter sees no file it was not given; edges to files are resolved by the check engine, against the files the repository tracks.

## How it is tested

- `test/told.test.ts` (stage 55): which sentences are layering or EARS rules and which are not; sentence ends outside backticks and abbreviations; paragraphs over lines, list items and quotes read, and fences, tables and an identified item's section not; lifted items, ids and the setting off.
- `test/adapters.test.ts`: requirement headings, fields and the first sentence of Verified by, including one that runs on to indented lines; paths in headings; long fences; identifier patterns with groups or alternatives; Implements lines and headings as references; duplicate identifiers; what a path is; features, rules, scenarios, outlines, doc strings, tags and repeated titles; test counts and citations from titles only, parameterised tests, and calls inside strings, comments and regular expressions; issues, mentions and malformed lines; since stage 28 the YAML subset (folded, block and quoted scalars, flow sequences over lines, comments), properties with edges and recorded silences, and a reduced results file read as the report it came from and refused at another commit.
- `test/tests-polyglot.test.ts` (stage 35): one realistic test file per language, with tests hidden in strings and comments that do not count, citations in every position, an identifier that does not match, a results join and a check that output does not depend on file order.
- `test/tests-join.test.ts` (stage 35): Surefire, Gradle, `go test -json` and cargo-nextest results joined to their test files, nested and dotted Java classnames, a `go.mod` module line, Rust inline modules, binaries and integration tests; a classname, package test or Rust test that two files fit, and one that none fits, left unmatched; `testBILL_7` citing `BILL-7` through the join only when the pattern cannot hold an underscore; and Jest and pytest results joined as before.
- `packages/run/test/items.test.ts`: the four adapters through the isolated runner, with globs and settings from a manifest, and the gaps the trace gives.
- `subjects/esi-ts`: ESI.ts at `2a2da8a`, whose counts its README records.

## Known limits

- Markdown links are not read as references; only backticked paths are ([A-96](../../ASSUMPTIONS.md)).
- A backticked path that names a file deleted on purpose is reported dangling like any other: telling the two apart needs history (stage 25).
- Gherkin identifiers follow titles, so a renamed rule is a new item ([A-99](../../ASSUMPTIONS.md)).
- Tests are found by `describe`, `it` and `test` calls in code with a literal title, including `.each(rows)(title)`, `.each<T>(rows)(title)` and ``.each`table`(title)``; titles built at run time are not read. A small lexer tells code from comments, strings and regular expressions; a slash after `return` is read as division, so a regular expression written straight after `return` can hide the call that follows it on that line.
- In Python, Java, Go and Rust, configured collection (pytest's `python_functions`, JUnit composed annotations, `#[test_case]`, an aliased `testing` import) is not read; an identifier in the middle of a camel-case name (`shouldRejectREQ_12`) does not cite; run-time skips (`t.Skip`, `skipif`) are not counted, and a parameterised test or subtest counts once.
- A result whose runner names a class, a package or a test binary joins only by the default layouts: a Java classname written as a display name (Surefire's phrased names) does not join; a Kotlin class, a Go module whose `go.mod` is outside the source and whose directories do not end its import path, and a Rust target at a path set in `Cargo.toml` (`[[test]] path`, `#[path]`) do not join; an rstest case (`test_fn::case_1`) does not join; and with no `Cargo.toml` in the source, a Rust result joins only when one file in the whole source fits. Each is counted as `results-unmatched`, never dropped.
